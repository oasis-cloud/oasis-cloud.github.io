
LLM 编码的劣势

1. 生成的代码量一旦变大，人将处于失控状态，无法做到胸有成竹状态。导致在迭代中无法准确评估改动范围。
2. 自然语言描述的需求变更，虽然生成 plan 后，可以留存，但是阅读比较耗时间，而且也是通过自然语言描述，存在歧义

为了消解上述问题，可以通过 DDD + DSL 的方式来进行约束。

DSL的优势：

1. 描述准确无歧义
2. 通过 DSL 进行描述，其形式类似于编写伪代码，这样可以提高人对于代码结构、业务逻辑的理解深度。
3. 在 DSL 形式化语言的约束下，可以减少LLM的问题求解空间，约束在小范围内。

DSL 的实施：
1. 定义 DSL
2. 实现 DSL
3. 在 LLM 模型启动的时候注入 DSL 上下文
4. 增加 DSL 转 React 、 Vue 等组件的约束
