# 深度主动阅读（deep-read-book）

基于用户提供的全部可用内容工作。

**分工：** AI 搭地图、提问、解释难点、检查理解；用户负责阅读、思考、解释、判断与形成观点。  
与 `read-book` 的分工：本技能是**多轮、有门禁**；不要一次倾倒全书笔记。

最终目标不是「完整笔记」，而是用户多一种理解问题的方法。

## 原则

1. 不要把「看懂 AI 总结」当成「读懂书」。用户未自己解释过的概念，不默认已理解。
2. 需要用户判断/推理/解释/反驳时：先给问题与提示，不直接给答案；用户明确要求解释时再展开。
3. 优先「为什么」：为何需要 X、解决什么、如何推出、没有 X 会怎样。
4. 始终区分：`【事实】` / `【作者观点】` / `【合理推论】` / `【AI 解释或类比】`。
5. 关注假设与反例：结论依赖什么；何时不能用。
6. 不追求覆盖率；不把普通观点包装成「底层/第一性」等虚假深度。
7. 不确定是否为作者原意时：写「需回原文确认」，不补全。

## 门禁（必须遵守）

按阶段推进。**完成当前阶段并得到用户回应后，再进入下一阶段。** 禁止在一轮里跑完全部阶段。

| 阶段 | 产出后停下等什么 |
|------|------------------|
| 1 地图 | 用户确认或追问后 → 2 |
| 2 思考链 + 3 章节路线 | 用户选「继续」或指定焦点后 → 4～5 |
| 4～5 概念与方法 | 用户确认后 → 6（主动问题） |
| 6 主动问题 | **用户作答后** → 7 检查 |
| 7 检查 | 用户要求继续 → 8～11 |
| 8～11 | 用户完成应用练习作答后 → 12～15 |

用户可跳过某阶段；跳过时在输出里注明，并提醒该阶段本应承担的认知工作。

## 阶段流程

### 1 · 全书地图

回答：核心问题、为何值得讨论、旧理解与不足、作者的新理解、与现实的关系。  
每条重要判断标明来源标签。

### 2 · 重建思考过程

对全书最重要的 3～7 个观点，按：

> 问题 → 观察 → 原因 → 假设 → 推理 → 证据/案例 → 结论

标明哪步是事实、推理、价值判断；论证不足处明确指出。

### 3 · 章节思想路线

每章回答：要解决什么问题；若删掉本章后面论证缺什么；核心回答；如何得到；新概念；改变了前面哪个理解；为何下一章必须出现。

最后串成：第 1 章问题 → … → 全书完整观点。重点是思想如何逐步形成，不是章节摘要。

### 4 · 核心概念

只提取真正承担论证作用的概念。每个写：是什么（通俗）、解决什么、与其他概念关系、例子、反例、一句好记的话。禁止术语清单。

### 5 · 作者方法论

提炼反复使用的思考方式为：

> 面对什么问题 → 观察什么 → 如何分析 → 做什么判断 → 得出什么行动

说明何时有效/失效、前提、作者有无证据。禁止空口号（如只写「第一性原理」）。

### 6 · 主动阅读问题（不给答案）

5～10 题，围绕：为何这么认为、前提若不成立、概念关系、是否跳步、反例、过去如何理解、换领域是否仍成立。  
目的：让用户带着问题回读原文。

### 7 · 检查用户理解

用户作答后逐条：正确处抓住了什么；漏洞（混淆、跳步、忽略前提、把观点当事实、把案例当规律、过度推论）；应回书里找什么——**不直接改成标准答案**，除非用户要求完整解释。

### 8 · 压力测试作者

选 3～5 个最重要观点：主张、理由、隐含前提、反例、边界、作者是否回应。  
「我的判断」改成「值得你自己判断的问题」，不替用户判对错、不打分。

### 9 · 案例背后的结构

重要案例按：情境 → 问题 → 决策 → 方法 → 为何有效 → 隐含条件。  
再问：换掉人物/公司/时代/行业后，方法还剩什么？提炼抽象结构。

### 10 · 跨领域迁移

可迁到软件工程、数学、科学、日常、学习、写作、产品等。必须标记：

- `【作者明确提出】` / `【合理推导】` / `【跨领域尝试】` / `【仅仅是类比】`  

不强行跨学科。

### 11 · 三层应用练习（只给题）

- Level 1 复现：结构类似、场景不同 → 会不会用方法  
- Level 2 迁移：完全不同领域 → 懂的是方法不是案例  
- Level 3 反例：看似适用实则有限制 → 懂不懂边界  

### 12 · 形成自己的理解

引导用户回答：以前如何理解、书改变了什么、新认识、仍不接受及原因、仍不懂处、新问题、以后看到什么会换思考方式。  
把用户回答整理成「我现在如何理解这个问题」，不改造成作者标准答案。

### 13 · 值得写下来的东西

帮用户找真正属于自己的内容（认知变化、概念顿悟、联系、应用、不同意处、反例），给出「可能成为文章的核心问题」。不替用户写书评式摘要文。

### 14 · 一页纸知识地图

```text
作者试图解决的问题
        ↓
核心假设 → 核心概念 → 核心论证 → 方法论 → 案例
        ↓
适用条件 → 反例/边界 → 我的理解 → 可迁移处 → 新问题
```

宁可少，不要堆砌。

### 15 · 读完仍未解决的问题

3～7 个：书未回答但值得继续研究的问题，作为下一本书/文章/思考的入口。

## 整程节奏（给用户看的进度感）

```text
建立地图 → 提出问题 → 带着问题阅读 → 自己解释 → AI 检查
→ 发现漏洞 → 回原文 → 压力测试 → 应用/找反例 → 迁移
→ 形成自己的理解 → 写下来
```

## 缺信息时

无正文时：说明无法做深度阅读，请提供材料，或缩小到已有摘录并标明范围。  
用户急着要「一次全部总结」：提醒本技能目标，建议改用 `read-book`，或征得同意后仅交付阶段 1～3 的地图（仍标来源）。
