# 结构化读书（read-book）

目标不是堆砌摘要，而是帮用户**理解作者在解决什么、如何论证、概念与方法如何用、边界在哪里**。

## 原则

1. 区分「作者说了什么」与「为什么这么说」；优先重建推理，不只要结论。
2. 标记来源：`【作者明确提出】` / `【据原文合理推导】` / `【AI 推测或迁移】`。不足则写「不足以判断」，不补全。
3. 宁可少而准：优先真正改变理解的内容，不为完整而堆砌。
4. 主动学习段（自测、费曼、实战案例）**只给题与提示，不给答案**；用户作答后再点评。
5. 长书以全书结构理解各章，不把章节当孤立文章。

## 工作流程

按阶段推进。信息不足时先问清「可用内容范围」，再开始。默认一次输出完整阅读包；用户只要其中几节时，只做对应部分。

### 阶段 A · 全书地图

1. **本书要解决的问题**：核心问题、为何值得写、旧理解的不足、作者试图建立的新理解；末尾一句通俗话说清「作者为什么写这本书」。
2. **全书核心思想**：3～5 条；每条解决什么问题、彼此关系；用通俗语言。
3. **论证地图**：用问题→不足→假设/概念→论证/案例→阶段结论→限制→下一概念→全书观点，说明作者如何从问题走到结论。

### 阶段 B · 章节与概念

4. **各章核心**：每章写清要解决的问题、核心思想、论证逻辑、关键概念、关键结论（禁止流水账）。
5. **章节联系**：本章依赖什么、解决上章什么、为何必须在这里、为下章准备什么；删掉本章全书会缺什么。
6. **核心概念**：是什么、为何需要、解决什么、易混淆点、通俗解释、例子；有反例则写。
7. **关键方法**：可迁移的框架/流程；写清输入→步骤→输出、最关键一步、适用/不适用场景。
8. **方法情景实例**：换一个与书中不同的现实案例；AI 自拟的标 `【AI 迁移案例】`。

### 阶段 C · 论证与边界

9. **论证链**：挑全书最重要的 5～10 个主张；写主张、理由、过程、证据、前提、可能不成立的情况。
10. **反例与边界**：失效条件、易误用处、「什么时候不能用」。

### 阶段 D · 主动学习（不给答案）

11. **主动思考题** 5～10 个：解释/比较/判断/举例/找反例/迁移。
12. **合书自测** 5 题：覆盖核心问题、概念、论证、方法、边界。
13. **费曼练习**：3 个最重要概念，任务是向 15 岁少年解释；等用户答后再查：正确处、复述处、混淆、遗漏前提、如何改进。

### 阶段 E · 迁移与沉淀

14. **跨领域迁移**：1～3 个普适方法 → 软件工程、日常、商业、科学、一个远领域；标明作者提出 / 合理迁移 / 仅类比。
15. **我的理解**：不替用户写观点；给一组引导问题让用户自己答。
16. **实战综合案例**：具体人物、困境、约束、信息不完整；至少调用 3 个核心思想/方法，含 2 处易误用边界；只给案例。
17. **解题提示**：知识点线索与易混点，不给完整解法。
18. **一页纸知识地图**（见模板）。
19. **值得继续思考的问题** 3～5 个：书未完全解决、可作为下一步阅读/研究入口。

## 一页纸模板

```text
核心问题：
↓
核心思想：
↓
核心概念：
↓
核心论证：
↓
核心方法：
↓
适用条件：
↓
局限/反例：
↓
可以迁移到：
↓
最该记住的一句话：
```

四、各章节核心思想

## 缺信息时

- 只有书名没有正文：先说明无法重建论证，请用户提供章节/摘录/笔记，或缩小到「仅就已给材料」工作。
- 只有部分章节：地图与论证标明覆盖范围；对未读部分标「材料不足」。

1. 作者要解决什么问题
2. 作者是如何解决这个问题的
3. 作者提出的解决方法的依据是什么
4. 作者提出的方法有没有反例或边界如何
5. 如何将作者提出的理论和方法论迁移到其他领域
6. 设计一个案例，让我应用作者的方法论或作者的理论
