## 计划说明（先读 3 分钟）

- **你的时间预算**：工作日每天 1–2 小时；周六、周日各半天（按 4 小时估算）。合计约 **13–18 小时/周**。
- **学习方式**（每次学习都按这个节奏走）：
  - **工作日（1–2h）**：40–60min 精读 + 20–40min 做“最小笔记” + 10–20min 用例/小练习（手写推导、做 1 个小实验或把概念复述出来）。
  - **周末（半天）**：以“整合”为主：补齐练习、做一个小项目切片、把本周笔记整理成可复用的模板（尤其是推理/概率/Transformer/Agent）。
- **主线与取舍**：
  - 以《**人工智能现代方法**》为“理论骨架”（你已完成前 6 章，所以从第 7 章开始）。
  - 以《**动手学深度学习**》补齐深度学习与 Transformer 必要知识。
  - 以《**动手学自然语言处理**》对齐 NLP 任务与预训练语言模型。
  - 以《**动手学大模型智能体**》落到“工具调用 / RAG / 规划执行 / 评测与安全”。
  - 《动手学机器学习》《动手学强化学习》只选与当下最有杠杆的章节做支撑（概率、评估、RLHF/PPO 的理解入口）。

## 第 1 周（2026-04-27 ~ 2026-05-03）：从“知识与逻辑”开始（AIMA 第 7 章）

### 工作日

  - 第2章 2.1–2.4（文本规范化：分词/子词/规范化）

### 周末（半天 + 半天）

- **输出**：做一份“命题逻辑速记卡”
  - 语法/语义、模型满足、归结、Horn 子句、前向/反向链接各写一个最小例子
  - **交付物格式（建议 1 页 A4/一屏）**
    - **符号表**：`P/Q/R...` 各代表什么（不超过 10 个）
    - **语法 vs 语义**：各用 2 句话解释 + 1 个例子（写出公式与它的含义）
    - **模型满足（⊨）**：给 1 个公式 + 2 个模型（一个满足一个不满足）
    - **归结（Resolution）**：写 1 个最小推导（2–4 步即可）
    - **Horn 子句**：写 2 条 Horn + 1 条非 Horn（并说明为什么）
    - **前向/反向链接**：各写 1 个“规则集合 + 查询 + 推导结果”
  - **验收标准**
    - 你能在 3 分钟内用这张卡回答：什么是满足？归结在做什么？Horn 为什么特殊？前向/反向链接适合什么场景？
- **小练习**：把一个前端业务规则（如优惠券叠加、权限判断）写成命题逻辑并做一次“推断/冲突检查”
  - **目标**：把“自然语言规则”变成“可推理的规则”，并能发现冲突/遗漏。
  - **准备**：任选一个你熟悉的规则（建议先选“权限判断”，比优惠券更少歧义）。
  - **步骤**
    - **1) 定义命题符号表（5–10 个以内）**
      - 例：`A=已登录`、`B=已实名`、`C=管理员`、`D=可访问页面X`、`E=触发风控`
    - **2) 把规则翻译成公式（每条规则 1 行）**
      - 例：`(A ∧ B) → D`（登录且实名才能访问）
      - 例：`C → D`（管理员直接可访问）
      - 例：`E → ¬D`（风控触发则禁止访问）
    - **3) 写 3 组“事实”（Facts）并推断结论**
      - Facts1：`A, B` 推出 `D`
      - Facts2：`C` 推出 `D`
      - Facts3：`A, B, E` 同时推导 `D` 与 `¬D`（出现冲突）
    - **4) 做一次“冲突检查”**
      - 若能推出 `P` 且也能推出 `¬P`，记录为冲突（解释是哪两条规则造成的）。
    - **5) 修正规则（选做）**
      - 给规则加优先级/例外条件：例如把 “风控” 写成更高优先级的约束，或把访问定义成“允许访问且不风控”。
  - **验收标准**
    - 你有一张“符号表”，至少 5 条规则公式，至少 3 组 Facts，并能明确指出是否存在冲突、冲突来自哪里。
  - **加分项**
    - 把“冲突”转成工程策略：例如“拒绝优先”或“显式白名单优先”，并说明理由。
  - **常见坑**
    - 命题符号太多导致写不下：把粒度收敛到“是否允许访问/是否满足条件”，先别把所有业务细节都塞进去。
    - 用“如果…那么…”时忘记区分充分/必要条件：例如“可访问 → 已登录”与“已登录 → 可访问”完全不同。

## 第 3 周（2026-05-11 ~ 2026-05-17）：一阶推断 + 规划入门（AIMA 第 9 章 + 第 11 章起步）

### 工作日

  - 第5章 5.1–5.6（过拟合/正则/评估/交叉验证：为后面模型训练打地基）

### 周末

- **小练习**：用“反向链接/查询”的方式写 5 个你关心的问题（像写 SQL 一样写查询意图）
  - **目标**：练习把“我想知道什么”写成可查询的形式，并能从结论反推需要哪些事实。
  - **准备**：选一个小领域（建议：权限/订单/风控/表单流程），先写 6–10 条“事实/规则”（用自然语言即可）。
  - **写法模板（像写 SQL 一样）**
    - `Query: CanAccess(user, page)`（用户是否能访问某页？）
    - `Query: WhyNotAccess(user, page)`（不能访问的原因是什么？）
    - `Query: Eligible(coupon, user, order)`（优惠券是否可用？）
  - **步骤**
    - **1) 写 5 个 Query（每个 Query 1 行）**：只写“要问什么”，不写答案。
    - **2) 对每个 Query 写 1 段“反向链接草图”**
      - 例：要证明 `CanAccess(u, p)`，需要 `LoggedIn(u)` 且 `HasRole(u, r)` 且 `RoleAllowed(r, p)` 且 `¬Risky(u)`。
    - **3) 为每个 Query 准备 1 组最小 Facts**
      - 让它“刚好能推出”结论，避免 Facts 太多导致看不出关键依赖。
  - **验收标准**
    - 5 个 Query + 每个 Query 都有“需要哪些子条件”的列表 + 每个 Query 至少 1 组最小 Facts。
  - **加分项**
    - 把 Query 分成 3 类：**可达性**（能不能）/ **解释性**（为什么）/ **找反例**（给我一个会失败的输入）。
- **输出**：把“规划问题”写成四要素：状态、动作、转移、目标（用一个你熟悉的前端场景类比：路由跳转/表单流程/工作流）
  - **目标**：把“流程/工作流”精确到可以写搜索/规划算法的程度。
  - **建议选题**（任选其一）
    - **表单流程**：多步表单（填写→校验→支付→完成）
    - **路由跳转**：不同页面之间受权限/登录态影响的跳转
    - **发布流程**：构建→灰度→全量→回滚
  - **四要素模板（照填）**
    - **状态 State（用向量描述）**：例 `{step, loggedIn, hasPaid, formValid}`
    - **动作 Action（动词）**：例 `{fill, validate, pay, next, back, submit}`
    - **转移 Transition（前置条件→结果）**：例 `if step=pay ∧ hasPaid=false then action=pay → hasPaid=true`
    - **目标 Goal（可检查）**：例 `step=done ∧ hasPaid=true ∧ formValid=true`
  - **最小例子（要求你真的写出来）**
    - 至少 6 个状态变量取值组合（可以用表格列出）
    - 至少 6 个动作
    - 至少 8 条转移规则（含 2 条“动作不可用”的前置条件）
    - 1 个目标 + 1 条“从初始状态到目标”的可行动作序列（手写即可）
  - **验收标准**
    - 别人拿到你的四要素描述，能复现同一条“可行序列”，并能指出哪里会失败（动作前置条件不满足）。

### 周末

- **小练习**：用朴素贝叶斯思路做一个“文本意图/垃圾邮件”最小例子（可以只写伪代码与流程，不要求上线）
  - **目标**：真正走完一次“训练—预测”的闭环，理解“先验/似然/后验”在分类里的位置。
  - **准备**
    - 选 2 个类别：`spam` vs `ham` 或 `intent=退款` vs `intent=查物流`
    - 手工造一个小数据集：每类 10–20 条短句（总计 20–40 条就够）
  - **步骤**
    - **1) 定义特征**：先用最简单的词袋（出现/不出现），不要一上来搞 TF-IDF/子词。
    - **2) 计算先验**：\(P(y)\)（每个类的样本占比）。
    - **3) 计算条件概率**：\(P(word \mid y)\)，并做拉普拉斯平滑（避免 0 概率）。
    - **4) 写预测流程**（伪代码即可）
      - 输入一句话 → 分词 → 对每个类别累加 `log P(y) + Σ log P(word|y)` → 取最大者。
    - **5) 做 5 条“新句子”测试**：每条写出模型预测 + 你认为的正确标签 + 解释（哪个词贡献最大）。
  - **验收标准**
    - 有一份数据集（可贴在文档里），能写出 \(P(y)\) 和至少 10 个高贡献词的 \(P(word \mid y)\)，并能对 5 条新句子给出预测与解释。
  - **加分项**
    - 做一个最小错误分析：挑 2 条错例，判断是“数据太少/词表太稀/表达方式不同”中的哪一种，并写 1 个改进点。
- **输出**：把“条件独立性”写成 3 个你自己的例子（至少 1 个来自工程/业务）
  - **目标**：能用“给定某变量后，两个变量是否还相关？”来表达独立性直觉。
  - **写法模板（每个例子 6 行搞定）**
    - **变量**：A=…，B=…，C=…（C 是你打算“给定/控制”的变量）
    - **直觉关系**：你认为 A 与 B 相关吗？为什么？
    - **条件独立判断**：给定 C 后，你认为 \(A \perp B \mid C\) 成立吗？为什么？
    - **可观测证据**：如果要验证，你会看哪 2 个指标/日志字段？
    - **反例**：什么情况下这个判断会失效（C 没建好/漏了共同原因）？
  - **建议选题**
    - 生活：天气(A) 与 带伞(B) 在 给定“看过天气预报”(C) 后是否独立？
    - 工程：接口慢(A) 与 前端 FCP 高(B) 在 给定“TTFB 高”(C) 后是否独立？
    - 业务：用户投诉(A) 与 次日留存下降(B) 在 给定“订单失败”(C) 后是否独立？
  - **验收标准**
    - 3 个例子里至少 1 个明确写出：A/B/C、你的独立性判断、以及你会去看的日志/指标。

### 周末

- **小练习**：把“束搜索/解码策略”写成你能在面试里解释清楚的 5 分钟口述稿
  - **目标**：能清晰解释“为什么需要解码策略”“束搜索在做什么”“和采样的区别”。
  - **口述稿结构（按这个背/讲）**
    - **1) 问题背景（30 秒）**：语言模型每步输出的是概率分布，解码=从分布里选 token 序列。
    - **2) 三种基本选择（60 秒）**
      - **贪心**：每步取最大概率，快但容易陷入局部最优/重复。
      - **束搜索**：保留前 \(k\) 条候选序列，按累计得分扩展，兼顾质量与搜索。
      - **采样**：按概率随机选（可加 `temperature/top_p`），多样性强但不稳定。
    - **3) 束搜索细节（90 秒）**
      - **打分**：对数概率累加；为什么用 log；为什么会偏向短句（长度偏置）。
      - **长度惩罚（length penalty）**：一句话解释它在解决什么。
      - **终止条件**：遇到 `eos` 怎么处理，什么时候停止扩展。
    - **4) 什么时候用哪种（60 秒）**
      - 翻译/摘要偏“确定性”：束搜索常见；对话/创作偏“多样性”：采样常见。
    - **5) 一个小例子（60 秒）**
      - 用 2 步、每步 3 个候选 token 的小表，口算演示贪心 vs 束搜索差异（写在纸上即可）。
  - **验收标准**
    - 录一段 5 分钟语音/文字稿（可附在笔记里），包含：定义、流程、优缺点、适用场景和一个例子。
